# mediagent MVP 規格

> 用途：本文件描述 mediagent 的 **MVP 範圍**需求；FR、BR、NFR 編號為全體文件與 issue 的共同依據。
> 結構化規格：資料模型見 `spec/erm.dbml`，驗收規格（Gherkin）見 `spec/features/`。
> 第 9 節「MVP 範圍外」的項目不在本規格定義；第 10 節為尚待團隊決定的事項。

---

## 1. 問題與目標

學生社團同時經營多個社群平台帳號（Threads、Instagram、Discord），同一則公告需要幹部逐一登入各平台重複發佈，常發生耗時、漏發、內容不一致、錯過發佈時間，以及無法確認各平台是否成功發出等問題。

mediagent 讓經授權的社團幹部只需撰寫一次貼文、選擇目標平台，系統就會立即或依排程時間發佈到各平台，並記錄每個平台的發佈結果。

**MVP 目標**：社團幹部撰寫一則貼文（文字，可附一張圖片），立即或依排程時間同步發佈到 Threads、Instagram、Discord，並能確認每個平台的發佈結果。

## 2. 使用者與角色

本系統只開放給經管理員授權、負責社團對外宣傳的幹部使用；一般社員沒有帳號，無法使用。角色只有下列三種。

| 角色 | 由誰擔任 | 說明 |
|---|---|---|
| 管理員 | 社長或公關長 | 管理平台帳號與幹部帳號，並擁有發佈者的所有權限 |
| 發佈者 | 負責發文的幹部，例如公關、文書 | 撰寫、發佈與排程貼文 |
| 撰稿者 | 協助撰寫內容的幹部，例如新進幹部、美宣 | 撰寫自己的貼文；不能發佈，也不能為草稿設定排程 |

本文件中的「使用者」指所有已登入的幹部，不分角色。系統另有內部的「系統」身分（排程發佈、逾時恢復等自動作業的操作者），不是使用者帳號，不能登入或操作。

### 2.1 角色權限

| 操作 | 管理員 | 發佈者 | 撰稿者 |
|---|:-:|:-:|:-:|
| 登入、登出、登出所有裝置 | ✓ | ✓ | ✓ |
| 建立貼文草稿 | ✓ | ✓ | ✓ |
| 修改、刪除自己建立的貼文（含附加或移除圖片、設定目標平台帳號） | ✓ | ✓ | ✓ |
| 將自己建立的貼文複製為新草稿 | ✓ | ✓ | ✓ |
| 修改自己建立、已排程貼文的排程時間；取消自己建立的貼文的排程 | ✓ | ✓ | ✓ |
| 預覽貼文、查詢貼文列表與發佈結果（含他人建立的貼文） | ✓ | ✓ | ✓ |
| 修改、刪除、複製他人建立的貼文 | ✓ | ✓ | |
| 立即發佈、為草稿設定排程、修改他人貼文的排程時間、取消他人貼文的排程、重試 | ✓ | ✓ | |
| 查看已連結的平台帳號 | ✓ | ✓ | ✓ |
| 連結、重新連結、移除平台帳號 | ✓ | | |
| 建立幹部帳號、查看幹部帳號、調整角色、停用帳號、啟用帳號、解除鎖定 | ✓ | | |
| 查詢稽核紀錄（含登入安全事件與平台授權事件） | ✓ | | |

停用的帳號不能執行任何操作（BR-20）。

## 3. 使用情境

### 情境一：管理員授權幹部

管理員將社團在 Threads、Instagram、Discord 的帳號連結至系統：Threads、Instagram 透過平台授權流程登入，系統取得帳號名稱、存取憑證與授權到期時間；Discord 由管理員貼上 Webhook 網址與頻道名稱，經系統向 Discord 驗證可用後才建立。接著管理員為負責管理貼文的幹部建立帳號，設定其 Email、名稱、角色與初始密碼。幹部即可使用該帳號登入。

換屆時，管理員將新任幹部的角色調整為管理員，再將自己的角色調整為其他角色或停用自己的帳號。

### 情境二：撰寫與發佈貼文

發佈者登入後撰寫一則貼文，可附加一張圖片，勾選要發佈的平台帳號，並預覽貼文在各平台呈現的樣子，再選擇立即發佈或設定排程時間。系統檢查內容字數與圖片符合所選平台的限制後，於指定時間將貼文發佈到各平台，並記錄每個平台的發佈結果。發佈者可從發佈結果看到各平台的狀態與貼文連結。

例：發佈者撰寫「本週三 19:00 社課在活動中心 201，主題是指彈入門，歡迎新生帶吉他來！」，附加一張社課海報，勾選 Threads、Instagram 與 Discord，將排程時間設為週二 12:00。週二 12:00 後，三個平台皆發佈成功，發佈結果顯示三則平台貼文連結。

若貼文沒有附加圖片，Instagram 不能被選為目標平台帳號。若圖片比例不符合 Instagram 的限制，系統自動從圖片中間裁切出 Instagram 用的版本，Threads 與 Discord 仍使用原圖；發佈者可在預覽中確認裁切後的結果。

### 例外情境：部分平台發佈失敗

發佈時 Threads 與 Discord 成功、Instagram 因平台暫時無法連線而失敗。系統將貼文標示為「部分失敗」，並記錄 Instagram 的失敗原因。發佈者重試後，系統只重新發佈到 Instagram，Threads 與 Discord 不會出現重複貼文。

若失敗的平台帳號已被移除而無法重試，使用者可將貼文「複製為新草稿」，重新選擇目標平台帳號後再發佈。

## 4. 資料

### 4.1 使用者帳號

社團幹部在系統中的帳號。

| 資訊 | 說明 |
|---|---|
| Email | 登入帳號；儲存前移除前後空白並轉為小寫，以標準化後的值判斷不可與其他帳號重複 |
| 名稱 | 顯示名稱 |
| 密碼 | 登入密碼，系統只保存安全雜湊值；初始密碼不可為空且至少 8 個字元，允許英文字母、數字及常見特殊符號，不強制特定組合 |
| 角色 | 管理員、發佈者、撰稿者三者之一 |
| 狀態 | 啟用或停用；停用的帳號不刪除，可由管理員重新啟用（啟用時 Email、名稱、角色維持原值） |
| 連續登入失敗次數 | 登入成功或管理員解除鎖定時歸零 |
| 鎖定到期時間 | 連續登入失敗達 5 次時設為當下加 15 分鐘；到達此時間即解除；未鎖定時為空 |

### 4.2 平台帳號

社團連結到系統的社群平台帳號。

| 資訊 | 說明 |
|---|---|
| 平台 | Threads、Instagram、Discord 三者之一 |
| 帳號名稱 | Threads、Instagram 為平台上的帳號名稱，以平台授權回傳為準；Discord 為頻道名稱，由管理員輸入 |
| 平台帳號識別碼 | Threads、Instagram 由平台授權回傳的穩定唯一識別碼，重新連結時以此判斷是否為同一帳號 |
| 授權狀態 | 有效或失效（失效條件見 BR-09） |
| 授權到期時間 | Threads、Instagram 以平台回傳為準，平台未提供時為空（未知）；Discord 為空（不適用）；不由管理員填寫 |
| 存取憑證 | Threads、Instagram 為平台授權取得的存取 Token，Discord 為 Webhook 網址；加密保存，不得出現在任何 API 回應、Log、錯誤訊息或畫面中 |
| 連結者 | 連結此平台帳號的管理員；重新連結時不變 |
| 已移除 | 移除平台帳號時不刪除資料，改標記為已移除；已移除者不出現在平台帳號列表、不能被選為目標平台帳號，其發佈紀錄與稽核紀錄保留 |

在未移除的平台帳號中，「平台＋帳號名稱」不可重複；已移除的帳號可再連結成新的一筆，舊的一筆保留。

### 4.3 貼文

一則要發佈到一個或多個平台帳號的公告。

| 資訊 | 說明 |
|---|---|
| 內容 | 貼文文字 |
| 圖片 | 附加的圖片，最多一張；可不附加 |
| 狀態 | 見 4.6 |
| 排程時間 | 預定發佈時間；未設定排程、取消排程、立即發佈已排程的貼文後為空 |
| 排程設定者 | 最後一次成功設定排程的使用者；從未設定排程時為空 |
| 建立者 | 建立此貼文的使用者 |
| 建立時間 | 由系統自動產生，使用者不可修改 |
| 進入發佈中的時間 | 立即發佈、排程發佈或重試受理時記錄，用於逾時恢復（BR-33） |

一則貼文可選擇一個或多個平台帳號作為目標平台帳號；同一則貼文不可重複選擇同一個平台帳號。

刪除貼文時，實際刪除貼文本身、目標平台帳號選擇與貼文圖片（圖片檔案不再被引用時刪除實體檔案）；發佈紀錄、發佈紀錄變更歷程與稽核紀錄保留原貼文 ID，不連帶刪除。

### 4.3.1 貼文圖片

| 資訊 | 說明 |
|---|---|
| 檔案格式 | JPEG |
| 檔案大小 | 單位為位元組；上限 8,000,000 位元組（1 MB = 1,000,000 位元組） |
| 寬度、高度 | 原圖的寬與高，單位為像素；須符合各目標平台的尺寸限制（數值待查證，見 4.7） |
| 公開網址 | 原圖的公開網址，Threads 與 Discord 使用 |
| Instagram 版本 | 符合 Instagram 長寬比的圖片（公開網址、寬度、高度）；原圖比例已符合時與原圖相同（裁切規則見 BR-06） |

### 4.4 發佈紀錄

一則貼文在一個目標平台帳號上的發佈結果。一則貼文的每個目標平台帳號各有一筆發佈紀錄，代表目前最新狀態。

| 資訊 | 說明 |
|---|---|
| 貼文 | 所屬的貼文；貼文刪除後仍保留原貼文 ID |
| 平台帳號 | 發佈到的平台帳號 |
| 狀態 | 待發佈、成功、失敗、已取消四者之一 |
| 發佈時間 | 發佈成功的時間 |
| 平台貼文連結 | 發佈成功時，該平台上的貼文網址 |
| 失敗原因 | 發佈失敗時顯示給使用者的固定原因：帳號授權過期、帳號授權失效、平台暫時無法連線、內容不符合平台限制、發佈逾時、其他 |
| 平台原始錯誤訊息 | 發佈失敗時平台回傳的原始訊息；只有管理員可查看；保存前須過濾存取 Token、密鑰等敏感資訊 |
| 發佈內容 | 實際發佈（含重試）時保存的完整文字；尚未實際發佈時為空 |
| 發佈圖片識別資訊 | 實際送出圖片的雜湊值（SHA-256）、格式、寬度、高度與版本（原圖或 Instagram 版本）；不保存圖片檔案本身 |
| 自動重試次數 | 逾時恢復時因平台確認未發佈而自動重新發佈的次數，上限 1 次 |

發佈紀錄的生命週期見 BR-26～BR-29。

### 4.4.1 發佈紀錄變更歷程

每筆發佈紀錄的建立與每次狀態實際改變，各新增一筆變更歷程；不可修改或刪除。

| 資訊 | 說明 |
|---|---|
| 發佈紀錄 | 所屬的發佈紀錄 |
| 變更前狀態 | 空值表示初次建立 |
| 變更後狀態 | 待發佈、成功、失敗、已取消之一 |
| 變更時間 | 變更發生的時間 |
| 操作者類型、操作者 | 使用者或系統；系統時操作者為空（背景發佈完成，包含重試完成時，操作者為系統） |
| 變更原因 | 受控代碼（顯示文字另行管理）：設定排程、立即發佈、新增目標平台帳號、修改目標平台帳號、目標平台帳號已移除、取消排程、重新排程、刪除貼文、發佈貼文：成功、發佈貼文：失敗、重試發佈：開始、重試發佈：成功、重試發佈：失敗、發佈逾時恢復：已確認發佈、發佈逾時恢復：確認未發佈、發佈逾時恢復：無法確認、自動重試發佈：開始、自動重試發佈：成功、自動重試發佈：失敗 |

狀態未改變的動作（例如只是啟動逾時檢查）不寫入變更歷程，而記錄於稽核紀錄。

### 4.5 稽核紀錄

重要操作的紀錄，供管理員追查。

| 資訊 | 說明 |
|---|---|
| 操作者類型 | 使用者或系統 |
| 操作者 | 執行操作的使用者；操作者類型為系統時為空 |
| 操作類型 | 登入、登出、登出所有裝置、建立幹部帳號、調整角色、停用帳號、啟用帳號、解除鎖定、連結平台帳號、重新連結平台帳號、移除平台帳號、發佈貼文、設定排程、取消排程、重試發佈、自動重試發佈、複製為新草稿 |
| 操作對象 | 被操作的帳號、平台帳號或貼文 |
| 操作時間 | 操作發生的時間 |
| 相關貼文 | 「複製為新草稿」時記錄新草稿 |
| 原因 | 「自動重試發佈」時記錄觸發原因（例如平台確認未發佈） |
| 排程設定者、貼文建立者 | 系統自動發佈時記錄 |
| 執行結果 | 「發佈貼文」「重試發佈」「自動重試發佈」結束後的貼文狀態 |
| 全域事件序號 | 稽核紀錄、登入安全事件、平台授權事件共用的全域唯一遞增序號 |

「發佈貼文」「重試發佈」「自動重試發佈」的稽核紀錄另保存當次各目標平台帳號的執行結果（狀態、失敗原因）；重試時列出全部目標平台帳號，未重試者標示原因（先前已成功、授權失效而跳過、已移除而跳過）。重試新增紀錄，不覆蓋先前的結果。

稽核紀錄不可被修改或刪除，保存至少一學年（NFR-08）。

### 4.5.1 登入安全事件

登入失敗的紀錄，與一般稽核紀錄分開存放，不放寬一般稽核紀錄的操作者規則。

| 資訊 | 說明 |
|---|---|
| 事件類型 | 登入失敗 |
| 失敗原因 | 密碼錯誤、帳號停用、帳號鎖定、帳號不存在（僅供內部追查，對外訊息一律相同） |
| 嘗試登入的 Email | 標準化後的值；屬敏感資訊，須妥善保護 |
| 對應帳號 | Email 對應到既有帳號時關聯該帳號；帳號不存在時為空 |
| 發生時間、全域事件序號 | — |

不得保存密碼；不可修改或刪除，保存至少一學年。

### 4.5.2 平台授權事件

連結或重新連結平台帳號失敗的紀錄，與一般稽核紀錄分開存放。

| 資訊 | 說明 |
|---|---|
| 事件類型 | 連結平台帳號失敗、重新連結平台帳號失敗 |
| 平台 | Threads、Instagram、Discord 之一 |
| 帳號名稱 | 帳號名稱或 Discord 頻道名稱；尚未取得時為空 |
| 平台帳號 | 重新連結失敗時為該平台帳號；首次連結失敗時為空 |
| 失敗原因 | 平台授權失敗、Webhook 驗證無效、暫時無法驗證、平台帳號識別碼不一致 |
| 操作者、發生時間、全域事件序號 | 操作者為執行連結的管理員 |

不得保存存取憑證、Token 或 Webhook 網址；不可修改或刪除，保存至少一學年。因帳號名稱重複而失敗屬資料衝突，不記錄為平台授權事件。

### 4.6 貼文狀態

| 狀態 | 代碼 | 說明 |
|---|---|---|
| 草稿 | DRAFT | 建立後的初始狀態 |
| 已排程 | SCHEDULED | 已設定排程時間，等待發佈 |
| 發佈中 | PUBLISHING | 正在發佈到各平台 |
| 發佈完成 | PUBLISHED | 所有目標平台帳號皆成功 |
| 部分失敗 | PARTIALLY_FAILED | 部分目標平台帳號成功、部分失敗 |
| 全部失敗 | FAILED | 所有目標平台帳號皆失敗 |

### 4.7 各平台的內容限制

| 平台 | 文字上限 | 圖片 |
|---|---|---|
| Threads | 500 字元 | 可不附加 |
| Instagram | 2,200 字元 | **必須附加**；寬度／高度須介於 0.8 與 1.91 之間（4:5 至 1.91:1，含兩端），不符合時由系統自動從中間裁切 |
| Discord | 2,000 字元 | 可不附加 |

- 字元數依各平台官方定義分別計算（換行、中文字、一般 emoji、組合 emoji 的算法以平台 API 文件為準，不明確時以實際 API 驗證）。
- 各平台的圖片寬高限制依目標平台分別驗證，數值待查證官方規格，不自行假設。

### 4.8 日期時間

- 一律以 UTC 儲存，API 傳輸使用帶時區的 ISO 8601（例如 `2026-10-06T04:00:00Z`）。
- 使用者輸入與畫面顯示一律為台灣時間（UTC+8），例如 `2026-10-06 12:00`。
- 排程時間、目前時間、授權到期時間的比較一律以 UTC 進行。

## 5. 功能需求

### 帳號與權限

| ID | 功能需求 | 來源 |
|---|---|---|
| FR-01 | 使用者應能以管理員建立的帳號（Email 與密碼）登入系統。 | 情境一 |

## 6. 商業規則

### 貼文內容

| ID | 規則 |
|---|---|
| BR-01 | 貼文文字不可為空白。 |
| BR-02 | 貼文文字長度不可超過所選目標平台中最嚴格的字數上限（見 4.7）；字數依各平台官方定義計算。 |

### 貼文圖片

| ID | 規則 |
|---|---|
| BR-03 | 每則貼文最多附加一張圖片。 |
| BR-04 | 圖片格式必須為 JPEG，檔案大小不可超過 8,000,000 位元組。 |
| BR-05 | 選擇 Instagram 平台帳號為目標時，貼文必須附加圖片；目標含 Instagram 時不能移除圖片，需先取消選擇 Instagram。 |
| BR-06 | 圖片寬度／高度在 0.8～1.91（含兩端）時，Instagram 版本與原圖相同；小於 0.8（過高）時從中間裁切成 4:5，大於 1.91（過寬）時從中間裁切成 1.91:1；只調整被裁切的那一邊，另一邊維持原圖尺寸；被裁邊長先四捨五入，若比例仍超出範圍，每次減 1 像素直到符合。Threads 與 Discord 使用原圖。 |

### 目標平台

| ID | 規則 |
|---|---|
| BR-07 | 發佈或設定排程前，貼文必須至少選擇 1 個目標平台帳號；草稿可以沒有目標平台帳號，已排程貼文至少保留 1 個。 |
| BR-08 | 目標平台帳號必須是已連結、未移除且授權狀態為有效的平台帳號。 |
| BR-09 | 平台帳號在下列情況授權狀態為失效：授權到期時間已過（到期時間為空者不因時間失效）；或發佈時平台明確回應授權無效（例如 Token 被撤銷）。網路錯誤、平台暫時性錯誤不改變授權狀態。重新連結成功後恢復為有效。 |
| BR-23 | 移除平台帳號時：自動從草稿與已排程貼文的目標平台帳號中拿掉；已排程貼文對該帳號的待發佈紀錄改為已取消；若它是已排程貼文唯一的目標，該貼文改回草稿、清空排程時間並取消原排程任務，內容、圖片、建立者保留。 |

### 排程

| ID | 規則 |
|---|---|
| BR-10 | 排程時間必須晚於目前時間，且以 5 分鐘為單位（分鐘數為 5 的倍數、秒數為 0）。 |
| BR-11 | 已排程但尚未發佈的貼文，可以修改內容、圖片、目標平台帳號與排程時間，或取消排程改回草稿。 |
| BR-24 | 修改已排程貼文的內容、圖片或目標平台帳號時，立即檢查發佈限制（BR-02、BR-05、BR-07、BR-08）；不符合則拒絕該次修改並保留原本的內容與排程；修改成功後維持已排程，排程時間不變。 |
| BR-25 | 排程時間到時，建立者已被停用的已排程貼文仍照常發佈。 |

### 貼文狀態

| ID | 規則 |
|---|---|
| BR-12 | 貼文狀態轉換只能依下列方式進行：草稿 → 已排程（設定排程）；已排程 → 草稿（取消排程，或唯一目標平台帳號被移除）；草稿或已排程 → 發佈中（立即發佈或排程時間到）；發佈中 → 發佈完成、部分失敗或全部失敗；部分失敗或全部失敗 → 發佈中（重試）。 |
| BR-13 | 只有草稿與已排程狀態的貼文可以修改或刪除。 |

### 發佈紀錄

| ID | 規則 |
|---|---|
| BR-26 | 發佈紀錄於設定排程或立即發佈草稿時，為每個目標平台帳號建立，狀態為待發佈；從未設定排程或立即發佈的草稿沒有發佈紀錄。 |
| BR-27 | 取消排程、刪除已排程貼文、已排程貼文拿掉某個目標平台帳號時，相關的待發佈紀錄改為已取消（不刪除）；已取消紀錄再次成為目標（重新排程或加回）時，同一筆改回待發佈，不新增紀錄。 |
| BR-28 | 已排程貼文修改目標平台帳號時，只更新受影響的紀錄：新增的目標建立待發佈紀錄、被拿掉的目標改為已取消、保留的目標不變；在同一個資料庫交易內完成。 |
| BR-29 | 已排程貼文改為立即發佈時，沿用既有的待發佈紀錄（不新增），只有待發佈紀錄會被執行；完成後排程時間清空。 |

### 發佈與重試

| ID | 規則 |
|---|---|
| BR-14 | 各平台帳號獨立發佈，任一平台帳號失敗不影響其他平台帳號的發佈。 |
| BR-15 | 所有目標平台帳號皆成功時，貼文為發佈完成；部分成功為部分失敗；全部失敗為全部失敗。 |
| BR-16 | 重試只針對發佈失敗的平台帳號；已成功的平台帳號不得重複發佈。 |
| BR-30 | 立即發佈與重試受理後立即回應，貼文改為發佈中；各平台帳號在背景發佈並逐筆更新發佈紀錄，全部結束後依結果判定貼文最終狀態。 |
| BR-31 | 排程時間到時，授權失效的目標平台帳號不發送，其發佈紀錄記為失敗、原因「帳號授權過期」；其餘平台帳號照常發佈。發佈時平台明確回應授權無效，原因記為「帳號授權失效」。 |
| BR-32 | 單一平台帳號發佈逾時（30 秒）時，記為失敗、原因「發佈逾時」；可重試，但重試前應提醒使用者先到平台確認是否已發出。 |
| BR-33 | 貼文進入發佈中的時間距今大於或等於 10 分鐘仍有待發佈紀錄時，系統執行逾時恢復：能向平台確認已發佈者記為成功；平台確認未發佈者自動重新發佈（每筆最多 1 次），結果依實際情況記錄；已自動重試 1 次、平台仍確認未發佈者記為失敗、原因「發佈逾時」，不再自動重發，使用者可手動重試；無法確認者記為失敗、原因「發佈逾時」，不重新發佈；之後依所有目標的結果重新判定貼文狀態。系統重新啟動時同樣執行恢復檢查，不直接重新發佈。 |
| BR-34 | 重試只處理平台帳號未被移除且授權有效的失敗紀錄；沒有任何符合條件的紀錄時拒絕重試，貼文狀態不變（授權失效者提示重新連結，已移除者提示改用複製為新草稿）。 |

### 刪除與複製

## 8. MVP 範圍

- 支援平台：Threads、Instagram、Discord
- 貼文內容：文字，可附加一張 JPEG 圖片；Instagram 必須附加圖片，比例不符時自動裁切
- 發佈前可預覽各平台呈現的樣子
- 角色：管理員、發佈者、撰稿者
- 帳號由管理員建立，不開放自行註冊
- Threads、Instagram 透過平台授權流程連結；Discord 以 Webhook 連結並驗證
- 平台授權到期後由管理員手動重新連結，系統不自動刷新授權
- 立即發佈、排程發佈、重試皆在背景執行，並有發佈逾時恢復機制
- 稽核紀錄、登入安全事件、平台授權事件、發佈紀錄變更歷程
